Message Moderation — XEP-0425

Lets a moderator of a group chat room retract another occupant's message for everyone in the room, as defined by XEP-0425: Moderated Message Retraction. Clients that support it, such as Conversations, offer a Moderate action on messages in rooms where you are a moderator.

What a moderation does

  • Every occupant's client is told to remove the message (an XEP-0424 retraction from the room, naming the moderator).
  • The message is replaced by a tombstone in the room's archive, so clients that fetch history through MAM get the tombstone rather than the text, and archive search no longer finds it.
  • It is replaced the same way in the join history new occupants are sent.
  • Occupants who were offline get the retraction when they next join the room, so their client removes its copy too.

Who can moderate

Only an occupant whose current role in the room is moderator. Room owners and admins are moderators by default. Everyone else gets forbidden. There is nothing else to configure.

Requirements

  • Openfire 5.0.5 or later. Openfire core supplies the occupant-ids (XEP-0421) and stanza-ids (XEP-0359) this builds on.
  • For archived history to be moderated as well, the room must have message logging on, and the Monitoring plugin serves it over MAM. Both copies of the message are tombstoned: core's conversation log and Monitoring's own archive, which is what MAM is served from by default.

Settings

System propertyDefaultMeaning
plugin.messagemoderation.enabled true Switching it off withdraws urn:xmpp:message-moderate:1 from service discovery at once, so clients stop offering the action.
plugin.messagemoderation.replay.days 30 How far back, in days, moderations are re-sent to an occupant when they join. Counted from when the moderated message was sent; at most 100 per join. 0 switches the replay off.
